# Визуализатор графа зависимостей пакетов

## Описание проекта

Программа предназначена для получения и анализа зависимостей пакетов с последующим построением графа зависимостей.

В качестве формата пакетов используется APT (Advanced Package Tool), применяемый в Ubuntu.

Приложение позволяет получать информацию о зависимостях из удалённого репозитория Ubuntu или использовать локальный тестовый файл с описанием графа.

Для получения и обработки данных используются стандартные библиотеки Python. Готовые менеджеры пакетов и сторонние библиотеки для получения зависимостей не применяются.

## Реализованные этапы

### Этап 1. Минимальный прототип с конфигурацией

Реализовано CLI-приложение с возможностью настройки параметров через командную строку.

Поддерживаются следующие параметры:

| Параметр | Описание |
|---|---|
| `--package` | Имя анализируемого пакета |
| `--repository` | URL репозитория или путь к локальному файлу |
| `--test-mode` | Режим работы приложения |
| `--max-depth` | Максимальная глубина анализа зависимостей |

Для обработки аргументов используется стандартный модуль `argparse`.

Реализована проверка корректности параметров. При запуске программы параметры выводятся в формате ключ-значение.

### Этап 2. Сбор данных

Реализовано получение информации о пакетах Ubuntu из индексов APT.

Основные возможности:

- Загрузка индекса пакетов по URL.
- Чтение локальных файлов с информацией о пакетах.
- Обработка форматов `Packages`, `Packages.gz` и `Packages.xz`.
- Разбор записей пакетов.
- Извлечение прямых зависимостей из полей `Depends` и `Pre-Depends`.

Для загрузки и обработки данных используются стандартные модули Python: `urllib`, `gzip`, `lzma`, `re`.

### Этап 3. Построение графа зависимостей

Реализовано построение графа зависимостей с учётом транзитивности.

Для обхода графа используется алгоритм BFS (поиск в ширину) без рекурсии.

Основные возможности:

- Получение прямых и транзитивных зависимостей.
- Ограничение глубины анализа.
- Обнаружение уже посещённых пакетов.
- Предотвращение бесконечного обхода при циклических зависимостях.
- Вывод построенного графа в консоль.

Для хранения графа используется словарь Python, где ключом является название пакета, а значением — список его зависимостей.

### Этап 4. Дополнительные операции над графом зависимостей

На данном этапе была реализована возможность поиска обратных зависимостей заданного пакета. Обратными зависимостями называются пакеты, которые используют выбранный пакет в качестве одной из своих зависимостей.

Для реализации использовался алгоритм поиска в ширину (BFS), применявшийся на предыдущем этапе. Сначала на основе информации репозитория формируется индекс обратных зависимостей. Затем выполняется обход графа, начиная с указанного пакета. Для ограничения глубины поиска используется параметр `max_depth`, а множество `visited` предотвращает повторную обработку пакетов и бесконечный обход циклических зависимостей.

Для включения нового режима был добавлен параметр командной строки `--reverse`. При его использовании программа выводит обратные зависимости, а без него сохраняется прежний режим построения графа.

Работоспособность была проверена на тестовом репозитории. Были рассмотрены случаи наличия нескольких обратных зависимостей, отсутствия обратных зависимостей, циклических связей между пакетами, а также ограничения глубины обхода.

В результате была реализована дополнительная операция над графом зависимостей, позволяющая определять, какие пакеты зависят от выбранного пакета.

### Этап 5. Визуализация графа зависимостей

На данном этапе была реализована генерация графического представления графа зависимостей с использованием языка диаграмм D2.

Для преобразования графа в описание D2 была разработана функция `generate_d2()`. Она получает словарь графа зависимостей, создаёт отдельный узел для каждого пакета и формирует направленные связи между ними. Направление стрелки соответствует направлению зависимости одного пакета от другого.

Полученное описание выводится в консоль. Для построения изображения его можно сохранить в файл с расширением `.d2` и обработать с помощью визуализатора D2.

Работоспособность была проверена на трёх пакетах тестового репозитория. Были рассмотрены граф с несколькими зависимостями, пакет без зависимостей и циклическая зависимость между двумя пакетами.

Для сравнения со штатными средствами Ubuntu APT использовалась команда apt-cache dotty, формирующая описание графа в формате DOT. Полученные графы могут отличаться из-за различий в версиях репозиториев, обработки альтернативных зависимостей, ограничений версий и архитектурных условий.

Таким образом, была реализована генерация текстового представления графа на языке D2, позволяющая визуализировать зависимости пакетов и анализировать структуру полученного графа.

## Формат тестового репозитория

В тестовом режиме используется текстовый файл, содержащий описание зависимостей пакетов.

Каждая строка имеет следующий формат:

```text
A: B C
B: D
C: D E
D: A
E: F
F:
G: H
H: G
```

Название пакета указывается слева от двоеточия, его зависимости — справа через пробел.

В тестовом режиме названия пакетов должны состоять из больших латинских букв.

## Запуск программы

Общий формат команды:

```bash
python main.py --package PACKAGE --repository REPOSITORY --test-mode MODE --max-depth DEPTH
```

### Работа с тестовым репозиторием

Пример запуска:

```bash
python main.py --package A --repository test_repo.txt --test-mode test --max-depth 3
```

В этом режиме программа использует локальный файл с описанием графа зависимостей.

### Работа с удалённым репозиторием Ubuntu

Пример запуска:

```bash
python main.py --package bash --repository https://archive.ubuntu.com/ubuntu/dists/noble/main/binary-amd64/Packages.gz --test-mode remote --max-depth 3
```

В этом режиме программа загружает индекс пакетов Ubuntu и извлекает информацию о зависимостях указанного пакета.

## Принцип работы алгоритма BFS

Построение графа осуществляется с помощью поиска в ширину.

Алгоритм начинает работу с исходного пакета, помещает его в очередь и последовательно обрабатывает найденные зависимости.

Для предотвращения повторной обработки пакетов используется множество `visited`.

Максимальная глубина обхода задаётся параметром `--max-depth`.

Исходный пакет имеет глубину 0, его прямые зависимости — глубину 1.

Использование множества посещённых пакетов позволяет корректно обрабатывать циклические зависимости и предотвращать бесконечный обход графа.

## Обработка ошибок

Программа предусматривает обработку следующих ошибок:

- Отсутствие обязательных параметров командной строки.
- Некорректное имя пакета.
- Неправильный URL репозитория.
- Несуществующий локальный файл.
- Ошибки загрузки и чтения данных.
- Ошибки распаковки индекса APT.
- Отсутствие указанного пакета в репозитории.
- Некорректный формат тестового файла.
- Повторное описание пакета в тестовом файле.
- Некорректные названия пакетов и зависимостей.
- Некорректное значение максимальной глубины.

## Ограничения текущей реализации

На текущем этапе программа извлекает названия зависимостей, но не разрешает альтернативные зависимости до конкретного пакета.

В тестовом режиме используется упрощённый формат описания графа.

Визуализация графа пока не реализована. Результат анализа выводится в консоль.
